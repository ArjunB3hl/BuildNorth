# Local voice prototype for the Mac WebKit app

On Apple Silicon, run `cd inference/pose-coach && bash tools/setup_stt.sh` once to install the pinned Parakeet and Kokoro models. This needs several GB of free disk space and downloads models from Hugging Face. Then from the repository root run `mac/local-voice/start.sh` and keep that terminal open. Pass the Mac app's bundle identifier as its optional argument for isolated test builds. If the service exited abnormally and reports an existing token file, first check that no service is running before manually removing that app container's `Library/Application Support/Rhythm/local-voice.token`.

Run a rebuilt Mac WebKit wrapper with a website build containing the matching changes. In Coach, select **Use local voice on this Mac**. ElevenLabs remains the default when available. Microphone speech is transcribed locally and the reply is synthesized locally. The transcript is sent to the Claude account signed into Claude Code on this Mac through a local MCP tool. Claude Code must be installed and signed in; no Claude API key is required. This may use your Claude plan's usage allowance. This test conversation is held only in the current app view and is not saved to Rhythm chat or linked to the signed-in Rhythm account. The service is half-duplex: it listens after each answer, with automatic pause detection, but cannot be interrupted while speaking.

This is a developer setup, not a self-contained distribution: it relies on the repository, Python environment, model cache, and a manually started helper. The currently deployed website and downloaded Mac builds do not contain these changes. Intel Macs are unsupported. Model startup takes time and may use several GB of memory. The helper binds loopback only and checks a per-app token; the web bridge is limited to the configured Rhythm origin and Coach page. It offers no CORS. The helper does not defend against a malicious process with the same macOS user privileges. Stop it with Ctrl-C when finished. No provider credentials are stored in the helper.

## Local Mac camera prototype

The local test website on `http://localhost:8113` can embed the local camera page. First run `cd inference/pose-coach && bash tools/fetch_assets.sh` to install the pinned camera, model and browser assets; these files are not checked into Git. Install the pose coach MCP runtime with `cd inference/pose-coach && uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python 'mcp>=2.3'`. Start its local server from that directory with `POSE_DATA_DIR=/tmp/rhythm-mac-camera-local POSE_MAC_PARENT_ORIGIN=http://localhost:8113 POSE_CLAUDE_TRANSPORT=cli POSE_COACH_MODEL=haiku .venv/bin/python server/dev_server.py --port 8765`. Keep the Mac voice helper running too; the wrapper uses it to check that Claude Code is signed in. In Camera workout choose Claude in the AI coach picker, or Auto if ElevenLabs is not linked. ElevenLabs remains first when connected.

The camera server is a developer service and is not bundled with the application. Its session logs can contain workout events and transcribed speech in `POSE_DATA_DIR/coach/`; do not use it for sensitive conversations unless that is acceptable. It is not a production deployment. A real device workout, microphone and camera permission still need testing in the Mac window.
